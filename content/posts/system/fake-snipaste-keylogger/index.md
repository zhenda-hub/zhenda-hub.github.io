装了一个截图工具，七个半月后这台机器每次开机几分钟内就硬死机，没有蓝屏，也没留下崩溃记录。

**它不是截图工具，是键盘记录器：把 22 万次击键、4.5 万次剪贴板、8,848 个窗口标题逐条写进本地日志。**

三层封装拆完，能确认的功能只有一个。

> **三条最重的事实**
>
> 一、**装完 13 秒，它把自己写进了杀毒软件的白名单**，所以七个半月无人发现。
> 二、**记录了两个多月，能查的 61 天里网络流量是 0**——没有证据表明数据被传走。
> 三、**解到第三层就停住了**：程序可以确认存在，但业务逻辑仍在加密段里。

## 先解释三个词

后面的内容绕不开这三个概念。

**校验码（CRC）**：每个数据块末尾都有 4 个字节，是这块内容的指纹。改动任何一字节就对不上，工具会报"文件损坏"。它用来证明数据没被动过。

**加壳 / 加密段**：程序代码原本是整齐的机器指令，加密后变成一片随机字节，反编译工具看到的就是乱码。这是让静态分析失效最省事的办法。

**熵**：衡量数据乱不乱的数值，范围 0 到 8。纯文本约 4，正常程序约 6.2，**8.00 意味着完全随机**——也就是加密或压缩。看到 8.00 就不必再试反编译。

## 它做了什么

时间精确到秒：12:38:52 下载，12:39:34 运行，12:40:01 释放到 `C:\ProgramData\<随机>\<随机>\`，**12:40:14 写入 Defender 排除目录**（事件 5007），12:40:30 注册开机自启服务（服务名随机 7 位）。

| 文件 | 大小 | 真实身份 |
| --- | --- | --- |
| `UTx6.exe` | 146 KB | 主体，代码段熵 8.00（磁盘上就是加密的） |
| `R.A` | 2.78 MB | 实为 DLL，111 个随机名导出 |
| `rZ9O.oe` | 15.36 MB | 实为一张完全合法的 PNG |

`UTx6.exe` 的导入表没加密，直接暴露用途：`OpenClipboard`、`SetWinEventHook`、`GetForegroundWindow`、`GetWindowTextW`、`GetKeyboardLayout`——键盘记录、剪贴板、窗口监控的标准组合，截图工具一个都不需要。

## 它是怎么藏的

**图片**：第一块解压出 1,440,600 字节，正好是一整幅 800×600 图的像素量，图像在第一块就结束。后面 1868 块与图像无关，只借用图片的块结构。**1871 个校验码全部算对**，所以看图软件和完整性检查都认为它正常。

**加密**：RC4，每块前 16 字节是密钥。解开得到 14.56 MB 明文，里面确实有一个 Windows 程序（能看到 `MZ` 头与 DOS 开场白）。但明文里还有一层"每隔 8-9 字节插一个杂字节"的处理，规则没吃透，程序头对不齐——这层是打包时做的，`R.A` 里没有解码器。

**API**：导入表只有一个 `KERNEL32`。它不写函数名，只写一个数字（哈希），运行时拿数字去目标 DLL 的名单里逐个比对。

哈希函数是自定义混合：FNV 质数 `0x1000193` 做乘法，掺入按位轮转和位置相关的移位，收尾借用 MurmurHash3 的散列终值。

```c
h = 0xc16dbb80;
for (i = 0; s[i]; i++) {
    h = (h ^ rotl(h,6) ^ s[i]) * 0x1000193 ^ (s[i] * 0x1f);
    if (i % 2 == 0) h += s[i] << (i & 3);
    else            h ^= s[i] >> (i & 3);
    h += (h >> 13) ^ (h << 7);
    h ^= (h >> 17) ^ (h * 0x800);
}
h = (h ^ (h>>16)) * 0x85ebca6b;   // Murmur3 fmix32
h = (h ^ (h>>13)) * 0xc2b2ae35;
return h ^ (h>>16);
```

算法是否算对，用真实指令验证过：

```asm
001F75FD  41 b8 40 83 0c 31     mov  r8d, 0x310C8340
```

`0x310C8340` 正是上面算法对 `LoadLibraryA` 算出的值，而 `r8d` 是 Windows 64 位调用约定里的第 4 个参数，也就是查找函数的入参。对上了。

**调用也做了混淆**：每次调用前先算一串运算得出目标地址再跳过去，60 多个函数都走这条路径，静态分析看不到"谁调用了谁"。

## 它到底记了什么

| 类型 | 数量 | 内容 |
| --- | --- | --- |
| 键盘记录 | 53,340 段 / **220,090 次按键** | 含 `lshift`、`lctrl`、`lwin`、方向键、回车 |
| 剪贴板 | **44,899 次**（去重 12,411 条） | 109 个网址、99 个邮箱或账号、13 条疑似密码或令牌、2 条疑似密钥 |
| 窗口标题 | 8,848 条（1,188 种） | 每次窗口切换都记 |

**546 段连续输入超过 12 个字符，最长一段 565 个字符。** 12 个字符以上基本就是密码长度或整条命令——密码是被逐字完整记录的。

日志用单字节异或 `0x62` 混淆、GBK 编码，破解成本是一行代码。解码后长这样：

```
[剪切板:]openclaw models status
[键盘记录:][lwin][lwin]
[标题:]OpenClaw 控制 - Google Chrome
[时间:]2026-4-1  14:48:5
```

## 有没有传出去

Windows 自带的"数据使用量"数据库（SRUM）按程序记录收发字节，保留 60 天。

| 证据 | 结果 |
| --- | --- |
| 该库 61 天 15,175 条，目标运行 16 次 | 关于它的记录 **0 条** |
| 每次运行前后 30 分钟的同机对照 | 其他程序 32~335 条，GB 级流量都在 |
| 导入表里的进程注入 API | 无 `WriteProcessMemory`、`CreateRemoteThread` |
| 配置文件主控地址 | 六个字段全空 |

三条互不依赖：没流量、统计功能确实在工作、没有借别的程序联网的手段。

**局限**：SRUM 只留 60 天，4 至 6 月不在窗口内。能作证 9 月 15 日后未外传，那段无法排除。

## 为什么没被发现

白名单让路径永不扫描，代码段加密让反编译失效，按哈希取 API 让导入表作废，调用弹板让调用关系不可还原，`cmd /c start` 让服务列表看不出真身，隐藏加系统属性让资源管理器看不见。

同机还查出：云保护 `MAPSReporting=0`、`PUAProtection=2`（仅审计不拦截）、实时保护在 4 月 15 日与 25 日各被关一次。

## 你可以怎么自查

1. **看杀毒软件的排除列表**，有没有自己没加过的路径——这一条最能说明问题
2. 到 `C:\ProgramData` 按名称排序，找随机字母数字命名的文件夹；勾选"隐藏"和"系统"、且删不掉的，是明确红灯
3. 任务管理器的"启动"标签里，找命令行以 `cmd /c start` 开头的服务
4. 查云保护是否被关：`Get-MpPreference` 的 `MAPSReporting` 为 0 通常不是用户自己关的

## 处置

1. 删排除项，开回云保护（`MAPSReporting=2`、`PUAProtection=1`），全盘扫描并换一家引擎复查
2. **改密码**——这 57 天输入过的密码都算泄露，要在另一台干净设备上改
3. 全盘普查同类形态：随机名目录 + 隐藏加系统 + 拒绝删除
4. 涉及资金账户时，重装是最干净的止损

## 三层封装的拆除进度

| 层 | 内容 | 状态 |
| --- | --- | --- |
| 外层容器 | 1871 个校验码全对的 PNG 块 | 完全拆开 |
| 加密 | RC4，每块前 16 字节为密钥 | 完全还原，标准向量验证通过 |
| 明文 | 14.56 MB，含一个 Windows 程序 | 有周期性字节插入，程序头对不齐 |
| 程序内部 | 9 个节，熵 8.00 | 仍然加密 |
| 调用关系 | 哈希解析 + 调用弹板 + 控制流扁平化 | 机制已识别，无法还原具体调用 |

净收益一句话：**能确认它记录输入、没有任何外传证据；但业务逻辑本身躺在第四层。**

## 附录一：可复现的命令

从卷影副本恢复被删的文件（绕过"拒绝删除"的权限设置）：

```powershell
mklink /d C:\vss9 \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy9\
robocopy "C:\vss9\ProgramData\2RpKK" "D:\out" /E /B /COPY:DAT /R:0 /W:0
```

`/B` 是备份模式，用管理员权限绕过 ACL。直接 `Test-Path` 或 `dir` 这类路径会失败，必须先 `mklink` 挂载。

查杀毒软件的配置变更，定位"被加白"那一刻：

```powershell
Get-WinEvent -LogName 'Microsoft-Windows-Windows Defender/Operational' -MaxEvents 2000 |
  Where-Object { $_.Id -eq 5007 -and $_.Message -match 'Exclusions' }
```

解析 SRUM（数据库被系统独占，要用 `/B` 复制；纯 Python，不需要编译）：

```powershell
robocopy C:\Windows\System32\sru C:\tmp\_sru SRUDB.dat /B
uv venv srumenv; uv pip install dissect.esedb
```

表名是 GUID，与功能的对应关系：

| 表 | GUID |
| --- | --- |
| 网络用量 | `{973F5D5C-1D90-4944-BE8E-24B94231A174}` |
| 网络连接 | `{DD6636C4-8929-4683-974E-22C046A43763}` |
| 应用时间线 | `{D10CA2FE-6FCF-4F6D-848E-B2E99266FA89}` |
| 能耗统计 | `{DA73FB89-2BEA-4DDC-86B8-6E048C6DA477}` |
| 应用使用统计 | `{5C8CF1C7-7257-4F13-B223-970EF5939312}` |

三个容易踩的坑：时间字段是以 1899-12-30 为原点的天数，被当成整数读出来了，要按 `struct.unpack("<d", struct.pack("<q", raw))` 重新解释；日志解码是 `bytes(b ^ 0x62 for b in data).decode("gbk")`；RC4 先过标准向量 `rc4(b"Key", b"Plaintext") == BBF316E8D940AF0AD3`，向量不过就是实现有问题，不要在样本上找原因。

## 附录二：四次误判

| 误判 | 事实 |
| --- | --- |
| 块尾 4 字节是自定义标签 | 是真实校验码，1871 块全部通过 |
| RC4 解出高熵数据说明密钥错 | 熵 7.98 正常——明文本身压缩过，判据应是能不能解压 |
| 服务指向的 exe 不存在 | 目录的"拒绝访问"权限骗过了 `Get-ChildItem` |
| 开机硬死机是固态硬盘省电 | 文件访问时间落在木马被拉起的 2 秒内，时间线指向载荷 |

共同点：**工具的返回值可能是假的，要换一条路交叉验证**。校验码用独立算法重算，目录内容用 `robocopy /B` 绕过权限重新列一遍。

## 附录三：哈希命中要算误报

有了算法和字典，还要过误报这一关。`R.A` 2.9 MB，字典 15,364 项，随机撞车的期望值是 `2.9e6 × 15364 ÷ 2^32 ≈ 10.4` 个。

| 扫描方式 | 命中数 | 判读 |
| --- | --- | --- |
| 直接按 4 字节扫全文件 | 7 个 | 低于期望值 10.4，属于噪音 |
| 加上"必须是指令编码"约束 | **2 个** | `LoadLibraryA`、`SHCreateShellItem` |

第一次扫出来的 7 个里有 `SymSrvDeltaName`、`pSetupStringTableStringFromIdEx` 这类明显不相关的结果，正是随机碰撞。加上指令模式约束后剩下的 2 个，上下文都是可解析的真实指令。
