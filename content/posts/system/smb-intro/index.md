U 盘拷来拷去、网盘先上传再下载——SMB 就是为了省掉这两步。它让另一台机器上的文件夹，在你的资源管理器或 Finder 里直接变成一个能点开的盘。双击一个 4 GB 的视频，数据走局域网，中间不落盘、不中转。

它是 **TCP 445 端口上的文件共享协议**，跑在局域网上最合适。

## 三个词先定义

**共享（share）**：服务端挑一个目录，挂个名字对外发布。别人只看见这个名字，真实路径不出门。

**UNC 路径**：`\\主机\共享名`。`\\192.168.1.10\media` 是一个完整的 SMB 地址，`smb://192.168.1.10/media` 是同一件事的另一种写法。

**账号与权限**：SMB 不是匿名协议。连上去要报用户名密码，能不能读、能不能写由服务端那份权限决定，客户端说了不算。

## 谁在提供它

协议只是一套报文格式，得有人实现：

| 角色 | 自带的东西 |
| --- | --- |
| Windows | 客户端 + 服务端都内置，文件夹右键「授予访问权限」就行 |
| macOS | 客户端内置，Finder 直接连；服务端在「设置 → 通用 → 共享 → 文件共享」 |
| Linux | 客户端 `smbclient`；服务端要装 **Samba** |
| iOS / Android | 文件 App、第三方文件管理器都能连 |

所以 **SMB 是协议，Samba 是实现它的一个软件**。Linux 上装的从来不是「SMB」，是 Samba 这个服务端程序；反过来，Windows 内置的 SMB 服务端也不叫 Samba。

## 版本：认 3 就行

- **SMB1**（CIFS）：1980 年代的东西，靠广播找主机、不加密，永恒之蓝走的就是它。Windows 10 1709 起默认不装。
- **SMB2**：Vista 起，砍掉了大量高频小请求，批量传输快一个档。
- **SMB3**：Win8 / Server 2012 起，加了传输加密、多通道、断点续传。今天值得在乎的只有它。

客户端和服务端会自动协商，取双方都支持的最高版本，不用手配。真需要操心版本的时候，是某台老设备只认 SMB1——那台设备才是该换的东西。

## 最小可用的路径

服务端（以 Windows 为例）：

1. 文件夹右键 → 属性 → 共享 → 添加账号，给「读取」或「读取/写入」
2. `ipconfig` 记下局域网 IP

客户端：

- macOS：Finder → 前往 → 连接服务器 → `smb://192.168.1.10/media`
- Windows：地址栏敲 `\\192.168.1.10\media`，勾上「记住凭据」
- iOS：文件 App → 右上角 … → 连接服务器

连上之后它就是一块盘：可以映射盘符、可以放快捷方式、可以在上面直接改文件。

## 四个真会撞上的坑

**1. 445 端口不通。** 能看见共享名却打不开，多半是 445 被防火墙或运营商掐了。要跨公网访问，走 VPN 或 Tailscale，别把 445 直接怼到公网上。

**2. 匿名访问默认是关的。** Windows 10 1803 起默认禁止 guest 匿名登录，前端报「不允许一个用户使用一个以上用户名」。别去抄「开启 guest」的注册表教程，建个账号给个密码更快。

**3. SMB1 早死透了。** 还报 SMB1 相关的错，说明对面是十几年前的 NAS 或老打印机。能升级就升级；非要开，只在内网开。WannaCry 走的就是 445 上的 SMB1 漏洞。

**4. 速度只有几 MB/s 时，先别怀疑 SMB。** 协议本身能跑满千兆，慢通常是 Wi-Fi 省电、百兆网线，或者单流撞上高 RTT。这类排查单独写过一篇：[Samba 传输速度只有 2 MB/s](/posts/life/samba-2mbps-wifi-powersave/)。

## 什么时候不该用它

- **Linux 之间共享**：NFS 更轻，权限直接沿用 POSIX，不用额外维护一套 SMB 账号。
- **跨公网 / 出差访问**：SMB 不是为不可信网络设计的，套一层 Tailscale 或 WireGuard 比暴露 445 安全得多。
- **只想传几个文件**：临时开个 HTTP 或 AirDrop 式方案，比配共享快。

## 一句话

SMB 不新，也不酷。但它是局域网里唯一一个 Windows、Mac、手机、电视盒子都默认认的共享协议——这就是它二十年没被换掉的原因。
